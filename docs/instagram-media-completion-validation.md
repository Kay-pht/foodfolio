## 目的と変更範囲

利用者の優先順位は、材料の一部欠落を受け入れ、解析失敗を減らすこと。Instagramのordered media解析とlegacy video解析だけ、Z.aiの`max_tokens`を10000、`reasoning_effort`をlowに変更する。textと他媒体は4000・effort未指定を維持する。prompt、入力順序、JSON形式、schema、120秒timeout、最小レシピ内容検査、retry、routingは変更しない。

前回の比較結果は[poc-ai-output-budget-results.md](poc-ai-output-budget-results.md)を参照。上限増加だけで採用せず、lowと組み合わせた候補を追加検証する。

## 採用方針と次の検証

10000＋lowは元投稿での打ち切りに対する緩和候補として残すが、分析失敗を解消した設定とは扱わない。今回のメディアルート固定では失敗4/15、ほうれん草には120秒直前の成功もあり、単純な上限増加だけでは安定性を満たしていない。

利用者の優先順位に合わせ、次は次の順で検証する。

1. **captionが十分な投稿で媒体解析を避ける。** 既存のtextルート・不完全時のfallbackと、Jevがメディアルートを選ぶ条件を実際の分類結果で確認する。今回の追加4投稿にはcaptionに材料・手順があり、caption中心の抽出との成功率・時間比較が可能。既存ルートがすでにtextを選ぶなら、その経路を維持する。元投稿はcaptionに十分な材料・手順がないため、別途mediaが必要。
2. **mediaが必要な投稿の入力を減らす。** 重複metadataや宣伝文を減らし、材料・工程を含む媒体の選択や動画入力の削減を比較する。多少の欠落を許容しつつ、title・材料・手順が保存できることを合格条件にする。現時点で入力削減がtimeoutを改善すると実測できたわけではない。
3. **schema不一致を具体的なfieldまで追う。** JSON objectモードに加え、失敗fieldの診断と必要な出力制約・正規化を検証する。[Z.ai公式API](https://docs.z.ai/api-reference/llm/chat-completion)のresponse_formatにはtext/json_objectが記載されており、このモデルでjson_schemaによる厳密強制が使えると確認したわけではない。schemaを無条件に緩める変更は今回行わない。

次の候補設定で、今回timeoutした2投稿とschema不一致の1投稿を含む同じ入力の繰り返し、保存・取得までのE2Eを再確認する。採用時はJSON失敗率・timeout率・所要時間を中心に評価し、欠落は別の品質記録として残す。これらの追加対策、実API比較、デプロイは今回未実施。
