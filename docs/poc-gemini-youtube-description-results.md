# Gemini 動画URL＋説明欄 PoC（2026-09-05）

## 結果

**動画URLと説明欄を同じGeminiリクエストに渡す方法は、無料枠で3/3成功。伊達巻の卵の分量・クリームチーズ欠落は今回改善した。一方、別の材料欠落が残るため本番品質に合格とはしない。**

Z.aiは使用していない。YouTube Data APIで説明欄を取得した後、Geminiへの生成リクエストは1動画につき1回。動画3本を各1回検証し、反復による安定性は未検証。

## 条件と再現方法

- 継続ブランチ: `codex/gemini-youtube-poc`。前回のPoC成果物を保持。
- モデル・Schema・temperature・maxOutputTokensは前回と同じ。
- 今回の変更は説明欄の追加に加え、説明欄による補完を許可し、分量の矛盾時は説明欄の明示値を優先するプロンプトへの変更。単純な入力追加だけの対照実験ではない。
- 既存の公開料理動画3本を使用。複数料理の動画は最初の1品を対象。
- 説明欄は公式YouTube Data API `videos.list(part=snippet)` で取得。完全な説明文を加工せずJSON文字列化して別パートで渡す。モデルへの正解データ・固定コメントの追加はしていない。
- YouTubeキーはFoodfolioの既存Secret Manager `foodfolio-dev-youtube-api-key` から読み取り、子プロセスの環境変数で渡した。キー値はログ・成果物に保存しない。
- Geminiの生成前に毎回Cloud Billing APIで `billingEnabled: false` を確認。所属先は前回同様 `continue-log`。クラウド設定・課金設定は変更していない。
- 説明欄取得失敗・課金状態不明・HTTPエラー時に停止し、自動再試行しない。

`GEMINI_API_KEY`、`YOUTUBE_API_KEY`、課金状態の読み取りに使うgcloud認証が利用できる環境で実行する:

```sh
npx tsx poc/ai-extraction/run-gemini-youtube.ts --with-description
```

前回の動画のみモードは引数なしで維持する。
