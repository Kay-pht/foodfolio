# foodfolio MVP UI/UX設計

## 1. 本書の目的

本書は、foodfolio MVPのワイヤーフレームで確定した画面構成・ナビゲーション・主要インタラクションを、実装時に参照できる形で文章化する。

詳細なビジュアルデザイン、配色、タイポグラフィ、最終ロゴは本書の対象外とする。

FigJamワイヤーフレーム：

https://www.figma.com/board/jL7FstV1ZltOhmeaIEHkOo

---

## 2. UI/UXの基本方針

- レシピ一覧をホームとする
- Bottom Tabは使用しない
- 画面遷移を必要以上に増やさず、Dropdown / Sheetなど同一画面上のUIを優先する
- 一覧は画像と料理名に絞り、情報を詰め込みすぎない
- URL保存はAI解析を待たずに完了させる
- タグ操作はレシピの文脈内で行い、MVPでは独立したタグ管理画面を持たない

---

## 3. グローバルナビゲーション

### 3.1 ホーム

レシピ一覧画面をホームとする。

ホームの主要要素：

- 左上：foodfolioアイコン
- 検索入力欄
- 2列グリッドのレシピ一覧
- 右下：URL追加用Floating Action Button（`+`）

### 3.2 Drawer

左上のfoodfolioアイコンを押すと、ホーム画面自体が右側へ移動し、左側からPush型Drawerを表示する。

DrawerのMVP項目：

- 設定
- アカウント

タグ管理はDrawerに置かない。

将来的に項目が増えた場合も、レシピ一覧の主要操作をDrawerへ詰め込みすぎない。

### 3.3 foodfolioアイコン

ロゴの方向性は「料理 × 本 / コレクション」とする。

最終ロゴデザインは別途決定する。

---

## 4. 認証

認証画面では以下を提供する。

- Appleで続ける
- Googleで続ける
- メールで続ける

メール認証では以下を扱う。

- ログイン
- 新規登録
- パスワードリセット

認証基盤の実装技術は後続の技術選定で確定する。

---

## 5. レシピ一覧

### 5.1 表示

レシピは2列グリッドで表示する。

各カードに表示するのは以下のみ。

- 画像
- 料理名

ジャンル、タグ、調理時間、出典等は一覧カードに表示しない。

### 5.2 検索への導線

ホーム上部に検索入力欄を表示する。

検索入力欄をタップすると独立したレシピ検索画面を開く。

### 5.3 URL追加

右下のFloating Action Button（`+`）を押すとURL追加Sheetを表示する。

Sheet内でURLを入力して保存する。

保存成功後はSheetを閉じ、レシピ一覧へ戻る。

AI解析はバックグラウンドで行う。

---

## 6. レシピ検索

### 6.1 基本構成

検索画面では以下を常時利用できる。

- テキスト検索
- ジャンルDropdown
- タグDropdown

ジャンル・タグは検索ワード入力前から表示する。

### 6.2 ワードなし検索

検索ワードは必須ではない。

以下をすべて可能とする。

- ワードのみ
- ジャンルのみ
- タグのみ
- ワード + ジャンル
- ワード + タグ
- ジャンル + タグ
- ワード + ジャンル + タグ

### 6.3 Dropdown

ジャンル・タグを押した場合、別画面やBottom Sheetへ遷移しない。

各コントロールの直下に候補を表示するDropdown形式とする。

ジャンル候補：

- 主菜
- 副菜
- 主食
- 麺
- スープ・汁物
- サラダ
- デザート
- その他

タグはユーザーが作成済みのタグから選択する。

タグ選択の単一選択 / 複数選択など詳細な検索演算は実装設計で確定する。

### 6.4 検索履歴

検索画面の入力前状態では、ジャンル・タグDropdownに加えて検索ワード履歴を表示する。

履歴対象は検索ワードのみとし、ジャンル・タグは履歴に残さない。

ルール：

- 新しい順
- 最大10件
- 同一ワードは重複保存しない
- 個別削除可能
- すべて削除可能

ワード入力またはフィルター適用後は検索結果を表示する。

## 7. レシピ詳細

### 7.1 タグ表示

付与済みタグは横方向にスライドできる形式で表示する。

タグ列の最後に `+` を表示する。

例：

```text
#簡単  #平日  #作り置き  ...  +
```

### 7.2 タグ追加

`+` を押すと、現在のレシピ画面の下からBottom Sheetを表示する。

別ページには遷移しない。

Sheet内には以下を表示する。

- 既存タグ候補
- 新規タグ入力欄
- 新規タグ追加操作

既存タグを選択すると、そのレシピへタグを付与する。

MVPではタグ名変更・タグ削除を行う独立した管理画面は持たない。

---

## 8. レシピ編集

編集可能項目：

- 料理名
- 材料名
- 分量
- ジャンル
- タグ

タグについては、編集画面の通常状態では付与済みタグと `+` のみを表示する。

付与済みタグは編集画面上で外せる。

`+` を押した場合のみ、編集画面の下からBottom Sheetを表示する。

Sheet内：

- 既存タグ候補
- 新規タグ入力欄
- 新規タグ追加操作

候補や新規入力欄を編集画面本体へ常時展開しない。

---

## 9. タグ機能のMVP範囲

MVPで行うこと：

- 新規タグ作成
- 既存タグのレシピへの付与
- レシピからタグを外す
- タグによる検索・絞り込み

MVPで行わないこと：

- 独立したタグ管理画面
- タグ名変更
- タグマスター削除
- レシピ一覧から複数選択してタグを一括付与 / 解除

将来的には、レシピ一覧で複数レシピを選択し、タグを一括で付け外しできる機能を候補とする。

---

## 10. 設定

Drawerから設定画面へ移動する。

MVPでは通知設定を提供する。

### レシピ解析通知

通知設定は1つのON / OFFとする。

ON：

- AI解析成功時に通知する
- AI解析失敗時に通知する

OFF：

- 成功時も失敗時も通知しない

成功・失敗で別々のトグルには分けない。

将来的に表示設定など、アプリ内動作に関する設定を追加する場所とする。

---

## 11. アカウント

設定とは別画面とし、Drawerから直接移動する。

MVPでは以下を表示する。

- ログイン情報
- ログイン方法
- ログアウト
- アカウント削除

ログアウトはアカウント削除より上に配置する。

将来的に以下を追加できる構造とする。

- プラン
- 支払い
- サブスクリプション

課金自体はMVP対象外。

---

## 12. MVP主要画面

| ID | 画面 / UI | 役割 |
| --- | --- | --- |
| SCR-01 | 認証 | Apple / Google / メール認証 |
| SCR-02 | レシピ一覧 | ホーム、2列グリッド |
| SCR-03 | URL追加Sheet | URLからレシピ保存 |
| SCR-04 | レシピ検索 | ワード検索、ジャンル・タグDropdown |
| SCR-05 | レシピ詳細 | レシピ閲覧、人数変更、タグ追加 |
| SCR-06 | レシピ編集 | 編集可能情報、タグ付け外し |
| SCR-07 | 設定 | レシピ解析通知など |
| SCR-08 | アカウント | ログイン情報、ログアウト、削除 |

補助UI：

- Push型Drawer
- ジャンルDropdown
- タグDropdown
- タグ追加Bottom Sheet

これらは独立画面として数えない。
