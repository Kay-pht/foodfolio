# foodfolio MVP 基本設計書

## 1. 本書の目的

本書は、foodfolio MVPについて、実装前に以下を明確にするための基本設計書である。

- ユーザーがどの画面をどのように操作するか
- 各画面に何を表示するか
- 主要な画面遷移
- URL保存からAI解析、検索、レシピ閲覧までの基本フロー
- loading / empty / error など主要な画面状態

詳細なデータベース設計、API設計、AIモデル選定、非同期処理方式、認証基盤の実装技術などは本書では確定せず、後続の技術選定・実装設計で扱う。

認証UIとして利用する方式は、Apple / Google / メールに決定している。

UI/UXの具体的な操作仕様は `docs/ui-ux-design.md` とFigJamワイヤーフレームを参照する。

---

## 2. MVPのプロダクト方針

foodfolioは、単なる「外部レシピへのブックマーク集」ではなく、外部サービスで見つけたレシピ情報を共通形式に整理し、ユーザー自身のレシピとして保存・検索できるアプリとする。

### 一言で表すと

**「ネット上で見つけたレシピを、自分専用のレシピDBとして整理して持つアプリ」**

YouTube、Instagram、TikTok、クラシル、クックパッド、その他WebサイトなどのURLを入口とするが、保存後の中心はURLではなくレシピ情報そのものとする。

元URLは削除せず、レシピ詳細画面から出典としてアクセスできるようにする。

### MVPで重視すること

1. URLを貼り付けた時点で保存を完了させる
2. AI解析完了をユーザーに待たせない
3. 外部サービスごとの差を吸収し、foodfolio内では共通形式で扱う
4. 保存したレシピを料理名・材料・タグ・ジャンルで探せる
5. 画面に情報を詰め込みすぎず、iPhoneで見やすいUIを優先する
6. 不要な画面遷移を増やさず、Dropdown / Sheetを適切に利用する
7. MVPでは保存・整理・検索に集中する

## 3. MVP対象範囲

### 3.1 対象

- iOSアプリ
- ユーザーアカウントあり
- Apple / Google / メール認証UI
- ユーザーごとにレシピを管理
- データはサーバー側に保存
- URLからレシピを登録
- iOS Share Extensionからの共有保存
- バックグラウンドAI解析
- レシピ一覧

- 検索・絞り込み

- 設定
- アカウント画面
- レシピ削除
- 元レシピへの遷移

### 3.2 MVP対象外

- URLを持たない自作レシピの新規作成
- 課金
- 保存件数制限
- AIによるタグ自動生成
- 独立したタグ管理画面
- タグ名変更
- タグマスター削除

- ユーザー間交流

- 人気ランキング
- レコメンド
- 調理時間による検索・絞り込み
- 一覧の並べ替え
- AI解析の手動再実行
- 人数変更結果の保存

## 4. レシピの基本データ

1レシピについて、MVPでは以下の情報を扱う。

| 項目                  | 必須 / 任意 | AI自動取得                  | ユーザー編集 | 備考                             |
| --------------------- | ----------- | --------------------------- | ------------ | -------------------------------- |
| 料理名                | 必須        | 対象                        | 可           | 保存直後は「解析中のレシピ」     |
| 画像                  | 任意        | AIではなく元URLから機械取得 | 不可         | 取得できない場合あり             |
| 材料名                | 任意        | 対象                        | 可           | 検索対象                         |
| 分量                  | 任意        | 対象                        | 可           | 人数変更時の表示計算に利用       |
| 人数                  | 任意        | 対象                        | 不可         | 原典の基準人数を保持             |
| 調理時間              | 任意        | 対象                        | 不可         | MVPでは検索対象外                |
| ジャンル              | 任意        | 対象                        | 可           | 固定候補から1つ                  |
| タグ                  | 任意        | 対象外                      | 可           | ユーザーが設定                   |
| 調理手順              | 任意        | 対象                        | 不可         | 取得できない場合は表示しない     |
| 元サービス / ドメイン | 必須        | 機械判定                    | 不可         | 主要サービス名、その他はドメイン |
| 元URL                 | 必須        | 入力値                      | 不可         | 詳細画面から開く                 |
| 保存日時              | 必須        | システム                    | 不可         | 一覧の並び順に利用               |
| AI解析状態            | 必須        | システム                    | 不可         | 非同期解析状態管理に利用         |

### 4.1 ジャンル

MVPでは1レシピにつき1ジャンルとする。

候補：

- 主菜
- 副菜
- 主食
- 麺
- スープ・汁物
- サラダ
- デザート
- その他

自由入力にはしない。

### 4.2 タグ

タグはユーザーごとに保持する。

MVPで可能な操作：

- 新規タグ作成
- 既存タグのレシピへの付与
- レシピからタグを外す
- タグによる検索・絞り込み

タグ名変更・タグ削除の管理画面はMVPでは持たない。

### 4.3 出典表示

主要サービスはサービス名を表示する。

例：

- YouTube
- Instagram
- TikTok
- クラシル
- クックパッド

上記以外の一般Webサイトはドメイン名を表示する。

## 5. AI解析の基本方針

### 5.1 保存と解析を分離する

```text
URL入力
↓
URL妥当性・重複確認
↓
レシピ保存
  料理名：解析中のレシピ
  AI解析状態：未完了
↓
URL追加Sheetを閉じてレシピ一覧へ戻る
↓
バックグラウンドで情報取得・AI解析
↓
解析結果をレシピへ反映
↓
一覧・詳細画面を更新
```

保存前にWebページタイトルを取得して仮タイトルへ利用する処理は行わない。

### 5.2 AI解析対象

可能な範囲で以下を取得する。

- 料理名
- 材料名
- 分量
- 人数
- 調理時間
- ジャンル
- 調理手順

調理手順を取得できなかった場合、そのレシピでは手順セクションを表示しない。

### 5.3 AI取得値とユーザー編集値

ユーザーが編集可能なのは以下。

- 料理名
- 材料名
- 分量
- ジャンル
- タグ

人数、調理時間、調理手順は原典から取得した情報として扱い、MVPでは編集不可とする。

将来AI再解析機能を追加する場合も、ユーザーが編集した値をAI結果で上書きしない。

### 5.4 情報未取得と解析失敗

#### 情報未取得

解析処理自体は正常に完了したが、元コンテンツに対象情報が存在しない、または抽出できる情報がない状態。

取得できない任意項目は空欄または非表示とし、原則として警告扱いにしない。

#### 解析失敗

ページ取得、解析処理、AI処理等が正常に完了しなかった状態。

レシピは保持し、取得済み情報をそのまま利用可能にする。

詳細画面では解析に問題があったことを通知する。

### 5.5 レシピ解析通知

設定画面に「レシピ解析通知」のON / OFFを1つだけ提供する。

ONの場合：

- 解析成功時に通知する
- 解析失敗時に通知する

OFFの場合：

- 成功時も失敗時も通知しない

成功・失敗でトグルを分離しない。

## 6. 人数変更と分量計算

### 6.1 基本思想

AIが原典から取得した人数を「基準人数」とする。

例：

```text
基準人数：2人前
鶏肉：200g
醤油：大さじ2
```

詳細画面でユーザーが一時的に4人前へ変更した場合、表示上の分量を比例計算する。

```text
表示人数：4人前
鶏肉：400g
醤油：大さじ4
```

### 6.2 保存しない

- 基準人数は変更しない
- 基準分量は変更しない
- ユーザーが選択した表示人数は保存しない
- 詳細画面を再度開いた場合は基準人数へ戻る

### 6.3 基準人数が取得できない場合

元レシピから人数を取得できなかった場合、人数変更UIは表示しない。

foodfolio側で「2人前」などの人数を推測・補完しない。

### 6.4 数値化できない分量

数値として比例計算できるものだけを変換する。

「少々」「適量」「お好みで」など数値化できない表現は原文のまま表示する。

## 8. グローバル画面構成

レシピ一覧をホームとする。

Bottom Tabは使用しない。

```text
レシピ一覧（ホーム）
├─ 検索入力欄 → レシピ検索
├─ 右下FAB（+） → URL追加Sheet
├─ レシピカード → レシピ詳細
└─ 左上foodfolioアイコン → Push型Drawer
                              ├─ 設定
                              └─ アカウント
```

foodfolioアイコンを押した場合、ホーム画面自体が右へ移動し、左側からDrawerを表示する。

Drawerにタグ管理は置かない。

---

## 9. 画面遷移

```text
[認証]
   ↓
[レシピ一覧]
   ├─ 右下 + → [URL追加Sheet]
   │              ├─ 保存成功 → Sheetを閉じて[レシピ一覧]
   │              └─ 重複URL → 既存レシピへの導線
   │
   ├─ 検索欄 → [検索]
   │              └─ レシピ選択 → [レシピ詳細]
   │
   ├─ レシピ選択 → [レシピ詳細]
   │                    ├─→ [レシピ編集]
   │                    ├─ タグ + → [同一画面上のBottom Sheet]
   │                    ├─→ [元レシピ]
   │                    └─ 削除 → [レシピ一覧]
   │
   └─ foodfolioアイコン → [Drawer]
                             ├─→ [設定]
                             └─→ [アカウント]
```

検索画面のジャンル・タグ選択は画面遷移ではなくDropdownとする。

レシピ編集画面のタグ追加も別ページへ遷移せずBottom Sheetとする。

### 目的

ユーザーを識別し、自分のレシピだけを利用できる状態にする。

### 表示

- foodfolio
- Appleで続ける
- Googleで続ける
- メールで続ける
- 認証エラー表示

### メール認証

- ログイン
- 新規登録
- パスワードリセット

### 状態

- 通常
- 処理中
- エラー

認証基盤の具体的な実装技術は技術選定工程で決定する。

## 11. SCR-02 レシピ一覧画面

### 目的

保存したレシピをシンプルに一覧表示し、アプリのホームとして機能する。

### レイアウト

2列グリッドとする。

### 一覧カード

表示は以下の2項目だけとする。

- 画像
- 料理名

調理時間、ジャンル、タグ、出典等は一覧カードには表示しない。

### 上部

- 左上：foodfolioアイコン
- 検索入力欄

検索入力欄をタップするとSCR-04へ移動する。

### URL追加

右下にFloating Action Button（`+`）を常設する。

押下するとSCR-03 URL追加Sheetを表示する。

### 並び順

保存日時の新しい順。

MVPではユーザーによる並べ替え機能を設けない。

### 解析中

保存直後は料理名として **「解析中のレシピ」** を表示する。

画像未取得の場合はプレースホルダーを表示する。

### Empty / Error

レシピ0件の場合はURL追加への導線を表示する。

一覧取得に失敗した場合は、エラーと再試行導線を表示する。

## 12. SCR-03 URL追加Sheet

### 目的

外部サービスで見つけたレシピURLをfoodfolioへ保存する。

### 表示

- URL入力欄
- 保存ボタン
- 入力エラー表示領域

### 保存フロー

```text
URL入力
↓
保存操作
↓
URL形式確認
↓
同一ユーザー内の重複確認
↓
保存
↓
Sheetを閉じる
↓
レシピ一覧へ戻る
↓
バックグラウンド解析開始
```

AI解析完了を待たない。

URL自体を保存できなかった場合はSheet上でエラーを表示し、再試行可能にする。

## 13. SCR-04 レシピ検索画面

### 目的

保存済みレシピから目的のレシピを探す。

### 13.1 常時表示

検索ワード入力前から以下を表示する。

- テキスト検索欄
- ジャンルDropdown
- タグDropdown

### 13.2 テキスト検索

1つの入力欄から以下を検索する。

- 料理名
- 材料

### 13.3 ジャンル・タグ

ジャンル、タグは各コントロールを押すと、その直下に候補を表示するDropdown形式とする。

別画面やBottom Sheetには遷移しない。

### 13.4 ワードなし検索

検索ワードは必須としない。

以下の組み合わせを許可する。

- ワードのみ
- ジャンルのみ
- タグのみ
- ワード + ジャンル
- ワード + タグ
- ジャンル + タグ
- ワード + ジャンル + タグ

タグの単一選択 / 複数選択等の詳細な検索演算は実装設計で定義する。

### 13.5 検索履歴

入力前状態では検索ワード履歴を表示する。

履歴対象はワードのみで、ジャンル・タグは履歴に残さない。

- 新しい順
- 最大10件
- 重複なし
- 個別削除可能
- すべて削除可能

### 13.6 検索結果

検索結果カードはレシピ一覧と同じく、画像と料理名のみ表示する。

条件に一致するレシピがない場合、その旨を表示し、条件を解除・変更できるようにする。

## 14. SCR-05 レシピ詳細画面

### 目的

foodfolio内でレシピ情報そのものを確認する。

### 表示情報

取得できているものについて以下を表示する。

1. 画像
2. 料理名
3. 人数
4. 調理時間
5. ジャンル
6. タグ
7. 材料・分量
8. 調理手順
9. 出典
10. 「元レシピを見る」ボタン

取得できていない任意情報は非表示を基本とする。

### 人数変更

基準人数を取得できている場合のみ人数変更UIを表示する。

数値化できる分量をその場で比例計算し、この操作は保存しない。

### タグ

付与済みタグを横方向にスライド可能なタグ列として表示する。

タグ列の最後に `+` を表示する。

`+` 押下時は同一詳細画面の下からBottom Sheetを表示する。

Sheet内：

- 既存タグ候補
- 新規タグ入力欄
- 新規タグ追加操作

別ページには遷移しない。

### 解析エラー

取得済み情報を表示した上で、解析に問題があったことを通知する。

単に元コンテンツに情報が存在しなかった場合はエラー表示しない。

### 削除

削除実行前に確認を行う。

削除後はレシピ一覧へ戻る。

MVPではアーカイブ・ゴミ箱は設けず、完全削除とする。

## 15. SCR-06 レシピ編集画面

### 目的

AI解析結果のうち、ユーザーが自分用に修正可能な情報を編集する。

### 編集可能

- 料理名
- 材料名
- 分量
- ジャンル
- タグ

### タグ編集

通常の編集画面には付与済みタグと `+` のみを表示する。

付与済みタグは編集画面上で外せる。

`+` を押した場合のみ、編集画面の下からBottom Sheetを表示する。

Sheet内：

- 既存タグ候補
- 新規タグ入力欄
- 新規タグ追加操作

候補や新規入力欄を編集画面本体に常時表示しない。

### 編集不可

- 画像
- 人数
- 調理時間
- 調理手順
- 元サービス / ドメイン
- 元URL
- 保存日時
- AI解析状態

### 保存

編集内容を保存するとレシピ詳細へ反映する。

ユーザー編集値は以後のマスターデータとして扱う。

## 18. 主要ユーザーフロー

### 18.1 初回利用

```text
アプリ起動
↓
Apple / Google / メールで認証
↓
レシピ一覧
↓
まだレシピがない状態
↓
右下 + からURL追加
```

### 18.2 レシピ保存

```text
レシピ一覧
↓
右下 +
↓
URL追加Sheet
↓
URL貼り付け
↓
保存
↓
Sheetを閉じてレシピ一覧へ即時復帰
↓
「解析中のレシピ」を表示
↓
バックグラウンド解析
↓
料理名・画像等を一覧へ反映
```

### 18.2.1 Share Extensionから保存

```text
Safari / YouTube / Instagram / TikTok等で共有
↓
Foodfolioを選択
↓
共有URLを確認して送信
↓
「確認中」を表示
↓
受付成功時は「✓ 送信」を表示
↓
レシピ一覧には通常のURL追加と同じ非同期解析結果が同期される
```

Share Extensionはログイン済みのFirebase認証状態をApp Group経由で共有し、AI解析完了を待たずに追加受付まで行う。

### 18.3 レシピ検索

```text
レシピ一覧
↓
検索欄
↓
検索画面
↓
ワード入力 または ジャンル / タグDropdownで条件指定
↓
検索結果
↓
レシピ詳細
```

ワードを入力せず、ジャンル・タグだけでも検索できる。

### 18.4 タグ追加

```text
レシピ詳細 または レシピ編集
↓

↓
同一画面の下からBottom Sheet
↓

↓
レシピへ反映
```

## 19. 主要状態設計

### 19.1 レシピ解析状態

| 状態                | UI上の扱い                                     |
| ------------------- | ---------------------------------------------- |
| 保存直後 / 解析待ち | 「解析中のレシピ」として利用可能               |
| 解析中              | 一覧・詳細を閲覧可能。取得済み情報があれば表示 |
| 解析完了            | 取得結果を通常表示                             |
| 部分的に情報なし    | 取得できた情報だけ表示。原則エラー扱いしない   |
| 解析失敗            | レシピは保持し、詳細で問題を通知               |

内部的な正式ステータス名は実装設計で定義する。

### 19.2 画像

- 取得済み：画像表示
- 取得前：プレースホルダー
- 取得不可：プレースホルダーを維持

### 19.3 通信エラー

ユーザー操作で再実行できる処理では再試行導線を提供する。

URL保存済み後のバックグラウンド解析失敗については、保存済みレシピ自体を削除しない。

## 21. 基本設計上の重要ルール

### Rule 1: URLは入口、レシピ情報が中心

一覧カードをタップしたとき、外部URLではなくfoodfolioのレシピ詳細を開く。

### Rule 2: 保存をAI解析に依存させない

URLが正常に保存できれば、解析前でもレシピとして一覧に存在する。

### Rule 3: Webタイトル取得を保存経路に入れない

保存直後は一律「解析中のレシピ」とする。

### Rule 4: AIが取得できない情報を推測で補わない

特に人数が不明な場合、foodfolio側でデフォルト人数を仮定しない。

### Rule 5: ユーザー編集を尊重する

料理名、材料、分量、ジャンル、タグについてユーザーが編集した値を優先する。

### Rule 6: 人数変更は表示上の計算

人数変更によって原典から取得した基準人数・分量を変更しない。

### Rule 7: 一覧はシンプルにする

一覧カードは画像と料理名のみ、2列グリッドで表示する。

### Rule 8: 画面遷移を増やしすぎない

検索フィルターはDropdown、タグ追加はBottom Sheetとし、不要な独立画面を作らない。

### Rule 9: タグ管理画面をMVPに入れない

タグはレシピの文脈内で作成・付与・解除する。

### Rule 10: 部分的に取得できなくても利用可能にする

一部の情報がなくても、取得できたレシピ情報を表示・検索・編集できる状態を維持する。

## 23. 基本設計の完了条件

以下を満たした時点でMVP基本設計完了とする。

- 必要な画面が列挙されている
- 主要画面間の遷移が説明できる
- URL保存から一覧反映までの操作を説明できる
- AI解析中・完了・失敗時のUI方針が説明できる
- レシピ詳細で表示・編集できる情報が明確である
- 人数変更と分量計算のユーザー体験が明確である
- ワード・タグ・ジャンル検索の組み合わせが明確である
- タグの作成・付与・解除方法が明確である
- 設定とアカウントの役割が分離されている
- ワイヤーフレームと文章仕様の間に大きな矛盾がない
